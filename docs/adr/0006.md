### ADR-0006: Sync Plan → Approve → Execute → Snapshot → Rollback lifecycle

- **Status:** Accepted
- **Context:** The big risk in PIM sync is destructive overwrites.
- **Decision:** Sync is a 2-phase process. Phase 1 builds an immutable `SyncPlan` with field-level diffs. Phase 2 executes it only if approved, first writing `Snapshot` rows (the previous WooCommerce state of each touched product). Rollback replays snapshots through the same adapter.
- **Consequences:** + safety, + demo moment, + audit trail. − storage for snapshots (trivial at this scale). Newly created products are rolled back by deletion (moved to trash).
